# FASE 6.1 — PORTABILIDADE, GIT, DOCKER E PREPARAÇÃO PARA VPS LOCAWEB

A Fase 6 está concluída ou em processo final de validação.

Agora preparar o projeto para:

* versionamento definitivo em Git;
* publicação em repositório privado;
* execução fora do Replit;
* deploy em VPS Linux hospedada na Locaweb;
* banco PostgreSQL próprio;
* Nginx como reverse proxy;
* HTTPS;
* backup;
* atualização segura;
* rollback.

IMPORTANTE:

Esta fase NÃO deve criar novas funcionalidades comerciais.

O objetivo é garantir que o sistema rode de forma independente do ambiente Replit.

---

# 1. OBJETIVO PRINCIPAL

Ao final desta fase, deve ser possível executar o sistema em uma VPS Linux limpa utilizando somente:

* Git;
* Docker;
* Docker Compose;
* arquivos do repositório;
* Secrets configurados no servidor.

O sistema não pode depender de:

* banco Replit;
* Secrets Replit;
* runtime proprietário do Replit;
* URLs internas do Replit;
* ferramentas exclusivas do ambiente de desenvolvimento.

---

# 2. ARQUITETURA DE PRODUÇÃO

Preparar para a seguinte arquitetura:

Internet
↓
HTTPS
↓
Nginx
↓
Aplicação Pedidos Gitex
↓
PostgreSQL

A aplicação e o PostgreSQL deverão preferencialmente executar em containers Docker.

O PostgreSQL NÃO deverá ficar diretamente exposto para a internet.

Somente os serviços necessários devem possuir portas públicas.

---

# 3. SISTEMA OPERACIONAL ALVO

Assumir como alvo:

Ubuntu Server LTS

em VPS Linux Locaweb.

Evitar dependências específicas de Windows/IIS.

Documentar versões mínimas/recomendadas de:

* Docker;
* Docker Compose;
* Git.

---

# 4. DOCKERFILE DA APLICAÇÃO

Criar um `Dockerfile` de produção.

Requisitos:

* utilizar imagem oficial estável;
* build multi-stage quando apropriado;
* instalar apenas dependências necessárias;
* gerar build da aplicação;
* executar com usuário não-root quando possível;
* expor somente porta interna necessária;
* não copiar Secrets para a imagem;
* não incluir arquivos desnecessários;
* não incluir cache, testes ou artefatos de desenvolvimento desnecessários.

Documentar o processo de build.

---

# 5. DOCKER COMPOSE

Criar:

`docker-compose.yml`

ou:

`compose.yaml`

Preparar pelo menos os serviços:

* app;
* postgres.

Opcionalmente:

* nginx

se fizer sentido manter Nginx também em container.

Preferência:

arquitetura simples e fácil de administrar.

---

# 6. POSTGRESQL

Configurar container PostgreSQL com:

* banco dedicado;
* usuário dedicado;
* senha via variável de ambiente;
* volume persistente.

Exemplo conceitual:

`postgres_data`

O volume deve sobreviver a:

* restart;
* rebuild;
* atualização da aplicação.

Nunca armazenar dados PostgreSQL dentro do filesystem temporário do container.

---

# 7. REDE INTERNA

Criar rede Docker privada.

Aplicação deve acessar PostgreSQL usando nome do serviço.

Exemplo conceitual:

`postgres:5432`

Não usar `localhost` entre containers.

Não publicar porta `5432` para a internet por padrão.
